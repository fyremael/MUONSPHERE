# Attention-sink stress test: multi-seed 10.68M-parameter causal LM

## Question

Does replacing Frobenius with Schatten-4 Muon initialization reduce a
deliberately induced attention sink? Can a fourth-order **attention**
concentration penalty or learned null route suppress sinks **without**
merely transferring attention to other keys or null, and without losing
causal language-model utility?

## Experimental controls

The initial 96-dimensional, two-layer testbench did not exhibit an
unregularized positive BOS excess at convergence. Here, an explicit
**synthetic stressor** adds +7.0 to the first-key logit on every
noninitial query of every attention head at all layers, before softmax.
This tests controlled robustness, not whether natural sinks emerge.
The calibration gate requires an absolute mean BOS increase above 0.35
and initial BOS share above 0.5 in **each** seed and arm; it fails rather
than treating a non-sink as a successful sink challenge.

The autoregressive task is BOS, 24 sampled symbols, separator, and
a repeated 24-symbol span, followed by EOS. Training minimizes whole
sequence cross entropy plus copy-region cross entropy. All methods
share data-generator seeds and initial common weight tensors. The
null-attention arm has additional per-head learned null logits, so
it is not parameter-exact to the other arms.

Architecture: six causal transformer blocks, width 384, eight heads,
normalization, position embeddings; approximately **10,684,416**
parameters in no-null arms. GPU: Tesla T4. Three training seeds
101/202/303. For each seed, run six methods for 120 update steps
and evaluate on the same fixed held-out minibatches:
AdamW; Muon/Frobenius; Muon/S4; Muon/S4 plus fourth-order
column-energy penalty; Muon/S4 plus null attention; Muon/S4 plus both.
No tuning per arm; same nominal steps, not compute or convergence matched.
Muon orthogonalizes eligible block matrices; other parameters use AdamW.
The independent reference Muon is not the repository's production optimizer.

## Correct interpretation of metrics

- **BOS mass**: absolute first-column probability on later copy queries.
- **BOS excess**: observed BOS probability minus causal uniform expectation
  *given real-token mass*. This distinguishes strong BOS preference from
  uniformly distributed probabilities.
- **BOS real share**: first-column probability divided by total attention
  to real tokens. This detects *false sink improvement* from routing
  everything to the null token.
- **High-sink-head fraction**: fraction of head/layer units with >50% of
  their mean real-token allocation placed on BOS.
- **Maximum column real share**: highest attention column after
  renormalizing the real-token mass per query. This detects relocation
  of concentrated attention from BOS to other keys.
- **Source-key real share**: mass on the source position containing the
  copy target, divided by total real-token attention. This indicates
  whether attention is redirected to useful content.
- **Null mass**: missing real-token probability sent to the learned null.
- **Held-out CE / copy accuracy**: task quality on stressed inputs.
- **Clean held-out CE / copy accuracy**: evaluate the same trained
  parameters without the synthetic BOS-logit perturbation.
- **BOS-ablation delta CE**: re-evaluate the trained model with first
  key removed from all noninitial attention rows. Negative delta means
  ablation improves accuracy under stress; positive delta means it
  harms accuracy. This intervention changes hidden-state propagation
  across all layers, not only the final attention matrix.

Sink reduction counts as **useful mitigation** only if the relative
BOS share decreases, source-information utilization does not collapse,
maximum column share does not simply shift to a different sink, and
held-out predictive quality is retained. A lower unnormalized BOS
probability alone is insufficient.

## Run in authenticated Colab

The single-file entrypoint is reproducibly generated by
`python experiments/build_stress_colab.py` and can be invoked without
separate module transfers:

```bash
colab run --gpu T4 --keep -s gcl-stress-big --timeout 5400 \
  experiments/attention_sink_s4_stress_colab.py \
  --width 384 --layers 6 --heads 8 --span 24 --batch 16 \
  --steps 120 --log-every 30 --eval-batches 3 \
  --seeds 101 202 303 --bos-bias 7 --lambda-conc 10 \
  --wandb-mode offline --out /content/gcl_attention_stress_big

colab download -s gcl-stress-big \
  /content/gcl_attention_stress_big/results.zip stress-results.zip
colab stop -s gcl-stress-big
```

Calibrated two-seed GPU smoke, also requiring a positive induction gate:

```bash
colab run --gpu T4 -s gcl-s4stress-smoke --timeout 600 \
  experiments/attention_sink_s4_stress_colab.py \
  --width 64 --layers 1 --heads 4 --span 8 --batch 4 \
  --steps 2 --seeds 101 202 --arms adamw muon_s4_null_conc \
  --eval-batches 1 --log-every 1 --wandb-mode disabled --self-test
```

Generated records include exact config, per-seed calibration, per-step
metrics, final comparison JSON/CSV, positive-control assertions and
offline W&B logs. Seed-by-arm training and validation streams are paired.

## Interpretation boundary

The stressor is **externally imposed**, not spontaneous. Even a method
that learns to circumvent it has not been shown to mitigate *natural*
BOS sinks from pretraining. Conversely, a model unable to circumvent
a +7 shift can still work well on unperturbed inputs. The next
experiment should use natural-language pretraining and native sink
emergence, with multi-seed matched validation loss and compute, rather
than extrapolate from copying to general-purpose language modeling.
